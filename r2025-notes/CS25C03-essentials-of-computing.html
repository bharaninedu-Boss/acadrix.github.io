1. Computer fundamentals

1.1 What is a computer?

A computer is an electronic, programmable system that accepts data as input, processes it according to instructions, stores data or results, and produces information as output. The word data refers to raw facts; information is data arranged or processed so that it is meaningful for a purpose.

Input→Processing→Output

↕ Storage supports the stages; control coordinates operations.

1.2 Characteristics

  • Speed: performs large numbers of operations in a short time.
  • Accuracy: produces correct results when the data, instructions and hardware are correct.
  • Diligence: does not become tired during repetitive work.
  • Storage: stores programs, input data and results for later use.
  • Automation: follows a prepared program with limited human intervention.
  • Versatility: can perform different tasks by changing its software.
  • Reliability: can repeat operations consistently when properly maintained.
Important limitation: A computer does not automatically know whether the problem or input is sensible. Incorrect data or incorrect instructions can produce incorrect results. This is often summarised as “garbage in, garbage out”.

1.3 Evolution of computers

Computer development can be studied through major technological stages. The generations are a useful historical classification, not a claim that every computer changed on one exact date.

GenerationMain technologyGeneral development
FirstVacuum tubesVery large systems, high heat and power consumption.
SecondTransistorsSmaller, more reliable and more energy-efficient systems.
ThirdIntegrated circuitsMany electronic components placed on a compact chip.
FourthMicroprocessorsPersonal computers and compact digital devices became widespread.
Later/current developmentsVLSI, parallel processing, networking and specialised processorsHigh-performance, mobile, connected and application-specific computing.

1.4 Classification of computers

  • Supercomputers: designed for very demanding calculations such as climate modelling and scientific simulation.
  • Mainframes: support large-scale transaction processing and many simultaneous users.
  • Servers: provide data, applications or services to other computers over a network.
  • Workstations: powerful single-user systems used for engineering, graphics and technical work.
  • Personal computers: desktops and laptops for general-purpose individual use.
  • Embedded computers: built into products such as vehicles, appliances and industrial controllers.

1.5 Applications

Computers are used in engineering design and simulation, manufacturing automation, banking, communication, education, healthcare, transport, scientific research, weather forecasting, entertainment and public services. In mechanical engineering, examples include CAD modelling, CAE analysis, CNC control, condition monitoring and production planning.

1.6 Basic organisation of a computer

Input unit→CPU→Output unit

CPU = Control Unit + Arithmetic Logic Unit + Registers

Main memory and secondary storage supply and retain instructions/data.

  • Input unit: accepts data and instructions and converts them into a form the system can process.
  • CPU: executes instructions. The Control Unit coordinates operations; the ALU performs arithmetic and logical operations; registers hold very small amounts of data at high speed.
  • Primary memory: memory directly used by the CPU during processing. RAM is generally volatile; ROM is non-volatile.
  • Secondary storage: retains data without continuous power, for example SSDs and hard disks.
  • Output unit: presents results through a monitor, printer, speaker or other device.
  • System bus: carries data, addresses and control signals between components.

2. Data representation

Digital computers use electronic states that are represented logically as two values, 0 and 1. A bit is one binary digit. A group of eight bits is a byte. Text, images, sound and numerical values are encoded as patterns of bits.

2.1 Units of digital information

UnitMeaning
Bit (b)One binary digit: 0 or 1.
Nibble4 bits.
Byte (B)8 bits.
KB, MB, GB, TBCommon larger storage units. In binary contexts, KiB = 1024 bytes; in decimal storage labels, kB = 1000 bytes.

2.2 How information is encoded

  • Integers: represented in binary; signed values can use methods such as two's complement.
  • Real numbers: commonly represented using floating-point formats, which have finite precision.
  • Characters: mapped to numeric codes. Unicode provides a standard way to represent characters from many writing systems.
  • Images: represented as pixels; each pixel stores colour or intensity information.
  • Audio: commonly represented by sampling a sound wave and quantising each sample.
  • Video: a sequence of image frames, usually accompanied by audio and timing information.
Why binary? Electronic circuits can reliably distinguish two ranges of signal states. Using two logical states makes digital storage and processing robust against small variations in voltage.

3. Spreadsheets for data operations and visualisation

A spreadsheet organises data in a grid of rows and columns. A cell is identified by its column letter and row number, such as B4. A formula normally begins with =.

3.1 Essential terms

  • Workbook: the spreadsheet file.
  • Worksheet: one sheet inside a workbook.
  • Cell: intersection of a row and column.
  • Range: a group of cells, for example A2:A10.
  • Formula: an expression entered by the user.
  • Function: a built-in calculation such as SUM or AVERAGE.

3.2 Common formulas

FunctionExamplePurpose
SUM=SUM(B2:B8)Add values.
AVERAGE=AVERAGE(B2:B8)Find arithmetic mean.
MIN / MAX=MIN(B2:B8)Find smallest / largest value.
COUNT=COUNT(B2:B8)Count numeric cells.
IF=IF(C2>=50,"Pass","Retry")Return a result based on a condition.

3.3 Example: laboratory readings

Suppose a student records five measured lengths in millimetres: 20.1, 20.0, 20.2, 19.9 and 20.1. Enter the readings in cells B2 to B6. Use =AVERAGE(B2:B6) to calculate the mean and =MAX(B2:B6)-MIN(B2:B6) to calculate the range. A column chart can compare readings; a line chart is useful when measurements are recorded in sequence.

3.4 Good data visualisation practice

  1. Choose a chart that matches the question: bar/column for category comparison, line for change over an ordered scale, scatter for relationship between two numerical variables.
  2. Give the chart a meaningful title.
  3. Label axes and include units.
  4. Use a suitable scale and avoid misleading truncated axes.
  5. Do not use unnecessary 3-D effects or excessive colours.
  6. Check that the chart represents the source data accurately.

4. Computational thinking

Computational thinking is a structured way of understanding a problem and developing a solution that can be carried out by a person or a computer. It is useful even when the final solution is not a computer program.

4.1 Four key approaches

ApproachMeaningExample
DecompositionBreak a large problem into smaller manageable tasks.Split a college attendance system into student records, attendance entry, calculation and report generation.
Pattern recognitionIdentify similarities or repeated behaviour.Notice that every monthly bill uses the same calculation structure.
AbstractionKeep the details relevant to the goal and ignore irrelevant details.For a route calculation, use distance and speed; ignore the vehicle's colour.
Algorithm designArrange clear steps to solve the problem.Calculate average marks using input, sum, division and output.

4.2 From a real-world situation to computable data

Before solving a problem, decide what must be measured or recorded. Identify the input, its type, its unit, acceptable limits and the output required. For example, a water-tank level monitor may use a sensor reading as input, convert it into a level estimate, compare it with a threshold and activate an alert.

  1. Understand the real-world objective.
  2. Identify relevant quantities and information.
  3. Represent each quantity using a suitable data type or unit.
  4. Define valid input ranges and exceptional cases.
  5. Develop and test a sequence of solution steps.
  6. Interpret the output in the real-world context.

5. Number systems and conversions

A number system defines the symbols and place values used to represent quantities. In a positional system, each digit's value depends on its position and the base (radix).

SystemBaseAllowed digitsExample
Binary20, 11011₂
Octal80–757₈
Decimal100–943₁₀
Hexadecimal160–9, A–F2B₁₆

5.1 Positional value

For a base-(b) number, each digit is multiplied by a power of (b), starting with power 0 at the rightmost integer digit. For example:

1011₂ = 1×2³ + 0×2² + 1×2¹ + 1×2⁰ = 8 + 0 + 2 + 1 = 11₁₀.

5.2 Decimal integer to binary

Repeatedly divide the decimal integer by 2. Record each remainder. Read the remainders from bottom to top.

Example: convert 25₁₀ to binary.
25 ÷ 2 = 12 remainder 1
12 ÷ 2 = 6 remainder 0
6 ÷ 2 = 3 remainder 0
3 ÷ 2 = 1 remainder 1
1 ÷ 2 = 0 remainder 1
Reading upwards gives 11001₂.

5.3 Binary to decimal

Multiply each bit by its positional power of 2 and add the results. Example: 1101₂ = 1×8 + 1×4 + 0×2 + 1×1 = 13₁₀.

5.4 Binary to octal and hexadecimal

  • For binary-to-octal, group bits in threes from the right. Add leading zeroes if required. Example: 110101₂ → 110 101 → 6 5 → 65₈.
  • For binary-to-hexadecimal, group bits in fours from the right. Example: 10111100₂ → 1011 1100 → B C → BC₁₆.

5.5 Decimal fractions

To convert a decimal fraction to binary, repeatedly multiply the fractional part by 2. Record the integer part of each product in order. Stop when the fraction becomes zero or when the required precision is reached. Some fractions repeat indefinitely in binary, so a finite representation may be approximate.

5.6 Quick hexadecimal values

Decimal 10 to 15 correspond to A, B, C, D, E and F. Thus 3A₁₆ = 3×16 + 10 = 58₁₀.

Check your conversion: Convert the answer back to the original base. If the value does not match, recheck the place values or the order of remainders.

6. Logic and Boolean reasoning

Propositional logic studies statements that are either true or false. A proposition is a declarative statement with a truth value. Example: “The measured temperature is above 50°C” is true or false for a particular measurement.

6.1 Logical operators

ORP ∨ QTrue when at least one of P and Q is true (inclusive OR).
ImplicationP → QFalse only when P is true and Q is false.
EquivalenceP ↔ QTrue when P and Q have the same truth value.

6.3 Boolean logic in computing

Boolean variables take values 0 or 1. The basic operations are NOT, AND and OR. They are used in decision conditions, digital circuits, search filters and control systems. For example, a machine may run only when guard_closed AND emergency_stop_released is true.

6.4 Useful laws

  • Identity: P AND 1 = P; P OR 0 = P.
  • Domination: P AND 0 = 0; P OR 1 = 1.
  • Idempotent: P AND P = P; P OR P = P.
  • Complement: P AND NOT P = 0; P OR NOT P = 1.
  • De Morgan: NOT(P AND Q) = (NOT P) OR (NOT Q).
  • De Morgan: NOT(P OR Q) = (NOT P) AND (NOT Q).
Application example: A warning lamp is switched on when the temperature is too high OR the pressure is too high. Define H as “temperature high” and P as “pressure high”; warning = H OR P.

7. Problem-solving basics

7.1 Define the problem clearly

A well-defined problem states the objective, inputs, required outputs, constraints and assumptions. Avoid starting to code before these are clear.

ElementQuestion to answerExample: average of marks
ObjectiveWhat must be achieved?Calculate the mean of three marks.
InputWhat values are supplied?m1, m2, m3.
ProcessWhat calculation is required?(m1 + m2 + m3) / 3.
OutputWhat must be displayed?Average mark.
ConstraintWhat values are valid?Each mark is within the allowed mark range.

7.2 Logical reasoning and decomposition

Logical reasoning uses facts and conditions to reach a conclusion. Decomposition divides the task into subproblems that can be designed and tested independently. A large application may be divided into input, validation, calculation, storage and reporting modules.

7.3 Algorithm: definition and properties

An algorithm is a finite, ordered set of unambiguous steps that transforms input into the required output to solve a problem.

  • Input: accepts zero or more clearly specified inputs.
  • Output: produces at least one result.
  • Definiteness: each step is precise and unambiguous.
  • Finiteness: terminates after a finite number of steps.
  • Effectiveness: each operation is sufficiently basic to be carried out.
  • Correctness: gives the required result for valid inputs.

7.4 Iteration and recursion

Iteration repeats a block of instructions using a loop. Recursion solves a problem by calling the same procedure on a smaller instance of the problem. A recursive solution must have a base case; otherwise, it may continue indefinitely.

IterationRecursion
Uses loop constructs such as for and while.A function or procedure calls itself.
Loop termination depends on a condition.Termination depends on reaching a base case.
Often uses less call-stack memory.Uses call-stack space for active calls.

7.5 Correctness and efficiency

Correctness asks whether the algorithm produces the required output for all valid inputs. Efficiency considers resources such as execution time and memory. An algorithm that works for five values may be too slow for five million values; consider both the size of the input and the growth in work as input size increases.

8. Fundamental algorithms

The following algorithms are core practice patterns. Trace each one with a small input before implementing it in a programming language.

8.1 Swapping two values

Use a temporary variable so that the first value is not overwritten.

START
INPUT A, B
TEMP ← A
A ← B
B ← TEMP
OUTPUT A, B
STOP

Example: A = 5 and B = 9. After swapping, A = 9 and B = 5.

8.2 Counting items

count ← 0
FOR each item in the collection
    count ← count + 1
OUTPUT count

The counter starts at zero and increases once for every item processed.

8.3 Summation of a set

sum ← 0
FOR each number x in the set
    sum ← sum + x
OUTPUT sum

For 2, 4, 6 and 8, the running totals are 2, 6, 12 and 20. Final sum = 20.

8.4 Factorial

The factorial of a non-negative integer n is the product of all positive integers from 1 to n. By definition, 0! = 1.

INPUT n
IF n < 0
    OUTPUT "Not defined for negative integers"
ELSE
    fact ← 1
    FOR i ← 1 TO n
        fact ← fact × i
    OUTPUT fact

Example: 5! = 1 × 2 × 3 × 4 × 5 = 120. For n = 0, the loop does not execute and fact remains 1.

8.5 Fibonacci sequence

In the common starting convention, the sequence begins 0, 1 and each next term is the sum of the previous two.

INPUT number_of_terms
a ← 0
b ← 1
REPEAT number_of_terms times
    OUTPUT a
    next ← a + b
    a ← b
    b ← next

For six terms: 0, 1, 1, 2, 3, 5. State the starting convention in your answer because some texts begin with 1, 1.

8.6 Reverse the digits of an integer

INPUT n
sign ← 1
IF n < 0
    sign ← -1
    n ← -n
reverse ← 0
WHILE n > 0
    digit ← n MOD 10
    reverse ← reverse × 10 + digit
    n ← n DIV 10
OUTPUT sign × reverse

Example: 472 → take 2, then 7, then 4; build 2 → 27 → 274. Note that leading zeroes in the reversed result are not retained as digits of an integer: 120 becomes 21.

8.7 Convert a decimal integer to another base

For a target base b from 2 to 16, repeatedly divide by b and collect the remainders. Reverse the remainders to obtain the answer. For bases above 10, map 10–15 to A–F. A zero input must be handled separately and produces 0.

INPUT n, base
IF n = 0
    OUTPUT 0
ELSE
    result ← empty sequence
    WHILE n > 0
        remainder ← n MOD base
        append digit_symbol(remainder) to result
        n ← n DIV base
    OUTPUT result in reverse order

8.8 Tracing table method

When asked to trace an algorithm, prepare columns for the loop variable, intermediate values and output. Record one row after each iteration. This makes it easier to identify the exact step where an incorrect result occurs.

9. Programming languages and program development

9.1 Program development life cycle

  1. Problem definition: understand the requirement and constraints.
  2. Analysis: identify inputs, outputs, processing and edge cases.
  3. Design: develop algorithms, flowcharts or pseudocode.
  4. Implementation: express the solution in a programming language.
  5. Testing and debugging: compare actual results with expected results and correct defects.
  6. Documentation: record design, usage and assumptions.
  7. Maintenance: correct, adapt and improve the program after delivery.

9.2 Types and levels of programming languages

  • Machine language: instructions encoded in binary and executed directly by the processor.
  • Assembly language: uses mnemonic instructions and requires an assembler.
  • High-level language: uses more human-readable constructs and is translated or interpreted by software tools.

9.3 Language implementation

A compiler translates a source program into another form, often machine code or an intermediate representation. An interpreter executes program instructions through an interpreter system. Modern language environments may combine compilation, bytecode and runtime interpretation; therefore, avoid assuming that every language uses only one method.

9.4 Programming paradigms

ParadigmMain ideaTypical example
ProceduralOrganises a solution as procedures or functions and step-by-step instructions.C, Pascal-style programs.
Object-orientedOrganises software around objects containing data and behaviour.Java, C++.
FunctionalEmphasises functions and expression evaluation.Haskell; functional features in many languages.
DeclarativeDescribes what result is required rather than specifying every execution step.SQL queries, logic programming.

9.5 Program design tools

Algorithms describe solution steps in plain structured language. Flowcharts show control flow using standard symbols. Pseudocode describes logic in a language-independent, code-like format. These tools help detect missing cases before implementation.

10.2 Flowchart: find the larger of two numbers

START→Input A, B→Is A > B?

↙ YES: Output A is larger     NO: Output B is larger (include an equality case in a complete design)

Output result→STOP

10.3 Pseudocode conventions

  • Use INPUT and OUTPUT for data entry and display.
  • Use ← for assignment.
  • Use IF / ELSE / END IF for decisions.
  • Use FOR or WHILE for repetition.
  • Indent statements inside a block.
  • Use meaningful variable names and state assumptions.

10.4 Example: check whether a number is even

START
INPUT n
IF n MOD 2 = 0 THEN
    OUTPUT "Even"
ELSE
    OUTPUT "Odd"
END IF
STOP

Test with 8 (even), 11 (odd) and 0 (even). Testing both branches and a boundary-like value helps reveal mistakes.

11. Scratch visual programming

Scratch is a block-based visual programming environment. Instead of typing every instruction, the learner connects blocks to create a script. It is useful for learning sequence, selection, repetition, variables, events and interactive design.

11.1 Main areas of the environment

  • Stage: area where the project runs.
  • Sprite: character or object controlled by scripts.
  • Blocks palette: groups of programming blocks.
  • Code area: place where blocks are joined into scripts.
  • Costumes: visual appearances of a sprite.
  • Sounds: audio assets used by a project.
  • Paint editor: create or edit sprites, backdrops and costumes.

11.2 Common block groups

Block groupPurposeExample use
MotionMove or rotate sprites.Move 10 steps; turn 15 degrees.
LooksChange appearance or show messages.Say “Hello” for 2 seconds.
SoundPlay and control sounds.Start a sound effect.
EventsStart scripts when an event occurs.When green flag clicked.
ControlLoops, decisions and stopping.Repeat, forever, if, wait.
SensingDetect user or environment interaction.Touching sprite?; key pressed?
OperatorsArithmetic, comparison and logic.Addition, greater-than, AND.
Variables / ListsStore one value or an ordered collection.Score variable; marks list.
PenDraw lines and shapes on the stage.Pen down, move, pen up.

11.3 Sequence, selection and repetition

  • Sequence: blocks run in the order they are connected.
  • Selection: an IF or IF-ELSE block chooses a path based on a condition.
  • Repetition: repeat, repeat-until or forever executes blocks multiple times.

11.4 Variables, input and data

A variable stores a value that can change, such as score, speed or age. A Scratch ask-and-wait block collects user input; the answer reporter provides the entered value. A list stores multiple related items and supports adding, deleting, replacing and reading items.

11.5 Example: simple score counter

  1. Create a variable named Score.
  2. When the green flag is clicked, set Score to 0.
  3. When the correct answer event occurs, change Score by 1.
  4. Display the Score variable on the stage.
  5. Test repeated correct answers and verify that the score increases once per event.

11.6 Nested loops and geometric patterns

A nested loop is a loop inside another loop. It is useful for repeating a group of actions for each row or each shape. For example, an outer loop can draw four squares; an inner loop can repeat the four sides of each square. If each side is 60 steps, move 60 and turn 90 degrees four times, then turn to the next starting direction.

11.7 Strings, lists, searching and sorting

A string is a sequence of characters. String processing may include joining text, finding length, extracting characters and comparing text. A list is an ordered collection of items. Searching finds whether an item exists and where it occurs. Sorting arranges items in an order, such as ascending numerical order or alphabetical order.

Linear search: examine items one by one until the target is found or the list ends. It works even when the list is not sorted. Sorting: repeatedly compare and rearrange items according to a defined rule; test with duplicates and already ordered input.

11.8 Recursion in Scratch

Recursion occurs when a custom block or procedure invokes itself. Design a clear stopping condition before the recursive call. A missing stopping condition can create an endless chain of calls.

Scratch practical record: Write the aim, blocks or script logic, input/event, expected output, actual observation and one test case. Include a screenshot of the running project if the practical format permits it.

12. Basic app development

App development applies problem-solving techniques to create a useful application on a selected platform. The syllabus emphasises modelling, iterative development, reuse, modularisation, algorithmic thinking, abstraction, decomposition, testing and debugging.

12.1 Development stages

  1. Identify a need: choose a real user problem and define who will use the app.
  2. Gather requirements: list the tasks the app must perform and its constraints.
  3. Model the solution: sketch screens, user actions, data and the flow between screens.
  4. Decompose: split the application into manageable features or modules.
  5. Build iteratively: implement a small working version, test it and improve it.
  6. Reuse: use suitable existing components or libraries rather than rewriting standard functions.
  7. Test and debug: check normal cases, invalid input and boundary cases.
  8. Evaluate: confirm that the app solves the original user problem.

12.2 Example: campus lost-and-found app

Design elementPossible specification
User problemStudents need a simple way to report and find lost items.
InputsItem name, description, date, location and contact method.
Core featuresSubmit a report, browse reports, search by keyword and mark an item as returned.
Data validationRequire an item name and reject empty descriptions.
ModulesReport form, listing, search, record storage and status update.
TestingValid report, missing item name, no search match, duplicate report and returned item.

12.3 Testing and debugging

Testing checks whether the application behaves as expected. Debugging is the process of locating, understanding and correcting the cause of a defect. A useful test set includes typical input, minimum and maximum valid input, invalid input, empty input and repeated actions. After fixing a defect, repeat the original test and related tests (regression testing).

12.4 Societal problem examples

  • Water-use reminder and daily consumption log.
  • Accessible campus navigation information.
  • Medicine or appointment reminder (without replacing professional advice).
  • Local waste-segregation information and collection schedule.
  • Public transport timing and route information.

14. Exam preparation and answer-writing

14.1 How to structure a descriptive answer

  1. Write a one- or two-sentence definition.
  2. Explain the principle or components in a logical order.
  3. Draw a neat labelled block diagram, truth table or flowchart if relevant.
  4. Give a worked example with intermediate steps.
  5. State an application or advantage where appropriate.

14.2 How to present a conversion problem

Write the given number and target base. Show division/remainder or positional expansion. Arrange the remainders correctly and clearly state the final answer with its base subscript. Check by converting back.

14.3 How to present an algorithm problem

State the input and output, list the algorithm steps, include a flowchart or pseudocode, trace the algorithm using sample values, and mention special cases such as zero, negative values or empty input when relevant.

5. Explain the program development life cycle and compare major programming paradigms.
6. Explain Scratch's environment and demonstrate sequence, selection, repetition, variables and lists through a small project.
7. Describe an iterative app-development process for a simple societal problem, including modelling, modularisation, testing and debugging.
